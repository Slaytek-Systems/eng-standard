# What the journeys do not reach yet

Ranked most bug-prone first: new code, code that decides a merge, and code that talks to GitHub come before stable or advisory output. The daily verification run takes the top item, writes its journey and feature file, runs it on main, and removes the item here. A journey that fails on main is a bug finding: report it, do not fix it in the same change.

1. **Self-merge decision** (`scripts/pr-gate.mjs merge`, `lib/self-merge.mjs`). It merges into this repo's main. Not shipped, and it calls `gh api`. Reach: a fake `gh` on PATH that serves PR, files, every page of statuses and comments JSON, then `node scripts/pr-gate.mjs merge --pr <n> --dry-run`; assert refusals for a verdict on another head, a FAIL, a `hold` label, a forged login and a behind branch. Since 0.23.0 also the run guard: a PASS held back while that verifier's `eng-run/<id>/...` status is pending, released by the owner's end or the deadline (timeout plus 300 s), a foreign end ignored, and a malformed status row or a context that looks like `eng-run` but does not parse refusing the merge.
2. **`eng merge gate` and `eng merge post`** (`merge.auto`, shipped for other repos). Post-merge red opens the exact inverse as an auto-revert PR. Reach: a scratch repo with `merge.auto` set, a fake `gh`, `eng merge post --dry-run`; assert the revert it would open.
3. **`eng verdict --pr <n>` and `eng verdict check --pr <n>`**. Posts the `eng-verdict/v1` comment and the `verdict` status, and reads verdicts back from comments. Reach: a fake `gh` that records the calls; assert the comment body carries the head SHA and runs, and that `verifier_logins` drops a comment from another login.
4. **Risk classification on a real diff**. `ship.high_risk.paths`, `version_only`, a rename's old path, and a change to the `ship.high_risk` block itself. Reach: `eng verdict check` on branches that change `package.json` version only, rename a file out of a high-risk path, and edit the block; assert the verifier count it demands.
5. **Upgrade from an older release**. A `.eng/lock.json` from another version and retired `gates.required` entries. Reach: `up` an older tag with `VERIFY_SRC`, `eng init`, then `up` main and run `eng sync --check` and `eng sync`; assert the drift message and the migrated config.
6. **Declared runs and leftovers** (`eng run <name>`, `eng run --keep`, `eng run down`, `hygiene.run_rules.ephemeral_runs`). Reach: a `project.commands` entry that leaves a file or a background process; assert `eng run <name>` fails and names it, and that `persist_env` exempts it.
7. **`eng init` on a repo that already ships**. Baselines so only new lint findings fail. Reach: a repo with an existing `.only(` test and a credential-looking filename, then `eng init` and `eng lint`; assert both are baselined and a new one fails.
8. **pre-push hook**. Blocks a force push and a push that deletes `main`. Reach: a bare remote in the run, then a forced push of a pushed branch (the spellings are in `test/no-force-push.test.mjs`); assert the hook refuses it and the remote ref is unchanged.
9. **Guard on edits and on Codex**. Claude Code Edit and Write into `.eng/guard`, the Codex hook format, and fail-open on bad input. Reach: Edit JSON on stdin to the Claude Code hook, the Codex hook through `.eng/guard/codex-hooks.json`, and malformed JSON; assert deny, deny, and allow with a stderr reason.
10. **`eng e2e --required` and `eng e2e --flake-check`**. Reach: `--files` lists with and without e2e paths, and `--results pass,fail,pass`; assert the JSON and the quarantine decision.
11. **`eng rules prove` and `eng lint` with repo rules**. Reach: a rule with a `proven_by.fixture` that does and does not trip it; assert prove passes and fails.
12. **`eng doctor --launch`**. Two concurrent launches of a `launch:` contract. Reach: a tiny `launch.up` and `launch.down` pair that binds a port; assert both runs pass and a contract that shares a port fails.
13. **Update notice** (0.20.0). eng says when a newer version exists. Reach: `ENG_STANDARD_SOURCE` at a checkout with a higher `package.json` version; assert the notice and its cache under `XDG_CACHE_HOME`.
14. **Skill visibility links**. `eng doctor` counts per tool after the user links `.claude/skills`. Reach: make the suggested links, rerun `eng doctor`; assert `81 of 81` for Claude Code.
